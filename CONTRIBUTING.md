# Contributing

Спасибо, что хотите помочь. Проект маленький, но требования к нему высокие:
пользователь доверяет приложению свои вес, диету и травму, поэтому «примерно
правильная» формула — это ошибка.

## Перед изменениями

```bash
npm install
npm run verify
```

`verify` должен проходить целиком. Если он красный — правьте или объясните,
почему нельзя.

## Правила, которые нельзя нарушать

### 1. Формулы — только с источником

Любая новая или изменённая формула требует:

- публикации (автор, год) в комментарии рядом с формулой;
- записи в [docs/CALCULATIONS.md](docs/CALCULATIONS.md);
- теста в `scripts/check-calculators.mjs`, где ожидаемое значение посчитано
  **вручную по публикации**, а не получено из самой реализации.

Тест, который повторяет формулу реализации, ничего не проверяет.

### 2. SI внутри, единица отображения — на экране

В `localStorage` и в расчётах — килограммы, сантиметры, годы. Ввод и вывод
конвертируются только через `toDisplayWeight`/`fromDisplayWeight` и
`toDisplayLength`/`fromDisplayLength`. Никогда не пишите `kg * 2.2` вручную.

### 3. Оба языка

Новый ключ добавляется в оба словаря — `ru` и `en` в `js/core/i18n.js`.
`npm run check:i18n` требует полного паритета.

Данные одинаково двуязычные: у упражнения есть `n` (RU) и `en`, у продукта,
мышцы, инвентаря и паттерна — тоже. Для отображения используйте аксессор
(`exName`, `foodName`, `muscleName`, `equipmentName`, `patternName`), а не
`m.n` напрямую. Для поиска — `muscleSearchText`, чтобы находилось в обоих
языках.

### 4. Никаких зависимостей в рантайме

Приложение — статика без сборщика. Новую библиотеку в `dependencies` не
добавляем. `devDependencies` — можно, если она нужна для проверок или сборки
(`jsdom` в `scripts/smoke-dom.mjs` — такой случай).

### 5. Новый экран — файл в `js/views/`

Экран экспортирует `render(params, ctx)` и возвращает DOM-узел. Маршрут
регистрируется в `ROUTES` в `js/app.js`, файл добавляется в precache в
`sw.js` — иначе экран не заработает офлайн (сборка это поймает).

`onboarding` закрыт гвардом `guard()` в `app.js` и виден только
незавершившим настройку.

### 6. Уважайте `prefers-reduced-motion`

Любая анимация — через `reducedMotion()` из `js/core/anim.js`.
`stagger()` принимает элемент, `NodeList` или массив.

### 7. Знак — один, ассеты — генерируемые

`assets/icons/icon.svg` — источник истины. PNG для веба и Android рисуются из
одного и того же кода в `scripts/lib/icon-render.mjs`, поэтому править надо
и `icon.svg`, и геометрию `PULSE` в библиотеке. Ничего не рисуйте вручную и не
кладите бинарные файлы в `res/`: `npm run verify` перегенерирует и веб-иконки,
и `android/.../mipmap-*`, и splash. Отдельного дизайна для Android нет и быть
не должно — иначе иконка в лаунчере разойдётся с иконкой в PWA.

## Проверка изменений

```bash
npm run check                    # быстрый цикл
npm run check:smoke              # если трогали интерфейс
npm run verify                   # перед коммитом
```

`check:smoke` поднимает настоящее приложение в jsdom и обходит все маршруты
в обеих единицах и обоих языках. Он ловит то, чего не ловит `--check`:
исключение при рендере, потерянный ключ перевода, русский текст в английском
интерфейсе.

## Стиль

- 2 пробела, точка с запятой, одинарные кавычки.
- Комментарий объясняет *почему*, а не *что*. `#` — для длинных блоков,
  `//` — короткие.
- Имена функций — глаголы (`render`, `navigate`), данные — существительные.
- Без магических чисел: константы с именем или комментарием с источником.

## Данные

Упражнения, продукты и шаблоны лежат в `js/data/`. `npm run check:data`
проверяет уникальность id, валидность ссылок и сходимость калорий с
макросами. Расхождение больше 20 % даёт предупреждение, а не ошибку: на
овощах вроде шпината разница в 7 ккал не имеет значения.

## Коммит

Понятное сообщение в императиве, описывающее что изменилось и почему.
Мелкие правки данных и изменения логики — отдельные коммиты.
